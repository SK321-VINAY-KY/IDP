# Per-document probe drives routing inside process_document (flag-guarded, default OFF)

Wires the in-process probe into the production pipeline as a pilot. `process_document` runs `probe_document_images` once over the already-supplied page images when `settings.probe_enabled` (env `IDP_PROBE_ENABLED`) is on and at least one page needs probing; `process_page` consumes `page_context["probe"]` at the existing seam, builds a single-task plan from the probe route used directly as the engine, records the probe dict in `PageMetadata.extra["probe"]`, and skips the dormant per-page hook for probed pages. probe.py was refactored so Phase B/C live in a shared core reused by both the standalone Lambda (`probe_document`) and the new in-memory entry point. With the flag off the whole block is a no-op.

Watch for: the shared-core observer now adds a VLM-overrides-script branch that the pre-feature standalone `probe_document` did not have — intended per the Option-B brief, but a real behavioral delta on the Lambda path that no standalone test pins down (likely). Everything else matches the approved intent.

**Verdict**: APPROVED

## High-level view

The gating is correct: `if settings.probe_enabled: _run_document_probe(pages, document_id)` sits before page dispatch and does nothing when off, so flag-off is byte-identical. The `process_page` seam prefers a per-document decision (`if "probe" in page_context`) and only then falls back to the `elif primary_task is not None` dormant hook, which is unchanged including its `IDP_ENABLE_PROBE` gate. Both flags on means the new probe wins and the old hook is never called for probed pages, asserted with a 0-call spy.

The probe route is used verbatim as `EngineTask.engine` (skip | paddleocr_printed | paddleocr_handwritten | vlm_transcribe), never remapped through `_ROUTE_TO_ENGINE`. `_ROUTE_TO_ENGINE` is used in exactly one place — translating the Layer-1 route vocab to engine-name vocab for the `needs_probe` pre-filter — which is a correctness fix, not a routing override, and keeps digital pages from being probed.

The lipika-vs-vlm telemetry and the VLM-overrides-confident-latin seam were lifted into `_make_observe` in the shared core, so both entry points emit the same `probe.lipika_vs_vlm` log and apply the same override. The standalone `probe_document` now calls `_sample_and_aggregate` / `_decide_pages` and its returned dict/stats are unchanged; its tests stay green. The one subtlety is that the shared observer added a new "VLM returned a different script → VLM wins" branch that the old inline `probe_document` observer lacked.

Failure handling is fail-safe: the probe call is wrapped in try/except that logs `probe.failed` and attaches no `probe` key, so every page falls back to today's routing and the document always completes. Pages the probe marks `not_needed` also get no key.

Supporting plumbing: magic-byte format detection at the VLM boundary (`BedrockScriptProbe._image_format`) picks png vs jpeg so the PNG bytes the pipeline supplies are valid to Converse; `scanned._get_paddle_engine` now caches per `(mode, lang)` with default `en`. No `.onnx` is tracked or staged, `docker/` and `step_functions/` are untouched in the feature diff, and `lambda_probe_handler.py` is untouched.

### Flag gating and byte-identity

`process_document` gains one guarded line before the serial/parallel dispatch:

```python
if settings.probe_enabled:
    _run_document_probe(pages, document_id)
```

With `probe_enabled` False (the default) this is a no-op and the rest of the function is untouched, so flag-off is byte-identical. `test_flag_off_is_byte_identical` asserts the deps are never built. The flag reads `IDP_PROBE_ENABLED` via the `IDP_` env prefix and defaults False.

### Route used directly as the engine; `_ROUTE_TO_ENGINE` only pre-filters

The seam prefers the per-document decision:

```python
if "probe" in page_context:
    _probe = page_context["probe"]
    primary_task = EngineTask(engine=_probe["route"], priority=1,
                              reason=f"probe:{_probe.get('route_reason', '')}")
    plan = [primary_task]
    if _probe.get("ocr_lang"):
        page_context["ocr_lang"] = _probe["ocr_lang"]
    metadata.extra["probe"] = dict(_probe)
elif primary_task is not None:
    _choice = _maybe_probe_route(...)   # dormant per-page hook, unchanged
```

`_probe["route"]` is already an engine name and is used verbatim — not remapped. The only `_ROUTE_TO_ENGINE` use in the new code is inside `_run_document_probe`, translating `route_from_profile`'s Layer-1 vocab (`digital`/`scanned`/`skip`) to engine-name vocab before `needs_probe`, because `needs_probe` compares against `docling`/`skip`. Without it digital pages would wrongly be probed; `test_digital_pages_never_probed` confirms they aren't (VLM call count 0, no `probe` key, engines stay `docling`).

### Shared Phase-B/C core

probe.py now exposes `_make_observe`, `_sample_and_aggregate`, `_decide_pages`, and `_rgb_from_image`. `probe_document` keeps rendering via fitz, uploading, and the S3 cache read/write, then calls the shared helpers; `probe_document_images` computes the same Phase-A CV signals in memory, encodes a JPEG only to feed the observer (no S3 put, `image_s3_*` absent), and calls the same helpers. The lipika-vs-vlm telemetry and the VLM-overrides-confident-latin seam live in `_make_observe`, so both paths log and decide identically.

The behavioral delta: the old inline observer in `probe_document` did, for a confident-latin page with the handwriting flag on:

```python
if v is not None:
    obs.handwriting_prob = v.handwriting_prob   # keep lipika's script
```

The shared `_make_observe` now does:

```python
if v is not None:
    if v.script and v.script != obs.script:
        obs = v                                 # VLM wins when it contradicts
    else:
        obs.handwriting_prob = v.handwriting_prob
```

So `probe_document` now changes its route when the VLM disputes a confident-latin guess — a case the standalone tests don't cover (the StubVLM there agrees on script). Per the Option-B brief this rule is meant to be in the shared core for both entry points, so treat it as intended but add a standalone contradicting-script test to lock it down.

### Failure handling

The probe call in `_run_document_probe` is wrapped so any exception logs `probe.failed` with `document_id` and returns without attaching any `probe` key; every page then runs today's routing and the document completes. `test_probe_raises_falls_back_and_document_completes` monkeypatches `probe_document_images` to throw and asserts both pages complete on `paddleocr_printed` with no `probe` key. Per-page decode errors inside `probe_document_images` are isolated to that page (`status="error"`, route `paddleocr_printed`) so one bad page never kills the document.

### VLM boundary format detection and Paddle per-lang cache

`BedrockScriptProbe._image_format` returns `png` for `\x89PNG`, `jpeg` for `\xff\xd8\xff`, else `jpeg`, and the detected value is passed as the Converse image format with raw bytes unchanged. `scanned._get_paddle_engine(mode, lang="en")` keys `_paddle_engines` by `(mode, lang)` and passes `lang` into both PaddleOCR constructors; `_ocr_convert` calls it with `lang=(ocr_lang or "en")`. No other ocr_lang plumbing was touched.

### Test coverage

`tests/test_pipeline_probe_document.py` adds 12 tests covering flag-off byte-identity, scanned-latin-printed with `ocr_lang=="en"` captured in the mocked Lambda payload, latin+hw0.9 → paddleocr_handwritten, non-latin → vlm_transcribe with `escalation_attempts==0`, blank → skip (VLM never sampled), the mixed document (docling/printed/skip/printed with `use_structure` only recorded), the heterogeneous document (VLM calls > 3 via widening + nearest-sample inheritance), probe-raises fallback, digital-never-probed, both-flags-on (new wins, `_maybe_probe_route` spy 0 calls), and VLM-call-count == n_samples (3). `tests/test_probe_inprocess_images.py` adds the in-memory entry-point and magic-byte unit tests. The standalone `tests/test_probe.py` stays green.

Not tested: the standalone `probe_document` path with a VLM that returns a script contradicting a confident-latin lipika guess (the new shared-core override branch).
