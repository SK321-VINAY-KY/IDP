# Probe Phase 2 — line-crop extractor, offline lipika eval, flag-gated handwriting

This change re-adds a flag-gated handwriting signal to the Layer 1.5 probe and adds two new offline/foundational pieces: a pure-OpenCV line-crop extractor (`line_crops.py`) and a developer-only lipika ONNX eval harness (`eval_lipika_crops.py`). The handwriting work threads an `Optional[float] handwriting_prob` end-to-end (types → vlm_probe → aggregate → probe → routing) behind `IDP_PROBE_VLM_FOR_HANDWRITING` (default on); when the flag is off or no handwriting signal is supplied, routing is byte-identical to today. The eval harness compares fp32 vs int8 under three preprocessing strategies on real dataset crops, labelling strictly from dataset folder structure and PDF origin (never from lipika/VLM). No `.onnx` is staged, and `docker/`, `step_functions/`, `src/ai/layer1_routing/` are untouched.

Watch for: nothing blocking. The flag-gated extra VLM call for confident-latin pages is the only behavioral change, and it is correctly placed in an `elif` so it fires exactly on the path that previously skipped the VLM (confirmed). The eval harness's default smoke run is CPU-heavy over the five Latin PDFs — the author added `--max-pages`/`--max-crops-per-source` to bound it, and the full run is deferred to the human per Phase 3 STOP (confirmed, informational only).

**Verdict**: APPROVED

## High-level view

The handwriting signal is reintroduced as an optional field that defaults to `None` everywhere, which is what keeps today's behavior intact: `decide_route` only consults `handwriting_prob` inside the existing `script == "latin"` branch, and only when it is non-`None` and at/above `cfg.hw_threshold`. No non-Latin path can reach `paddleocr_handwritten` or `paddleocr_printed` — every non-Latin confident script still escalates to the VLM (confirmed by reading `routing.py` and by targeted route checks for devanagari/telugu with `handwriting_prob=0.99`).

The one new VLM call is gated tightly in `probe.py` Phase B: it lives in an `elif` after the normal VLM-fallback `if`, so it only runs for the confident-latin, non-mixed case that previously skipped the VLM, and only when the flag is on and a VLM is configured. It copies only `handwriting_prob` off the VLM observation and keeps the ONNX script/confidence. Flag off → zero extra calls (test asserts `vlm.calls == []`).

The line-crop extractor reuses `imaging.ink_mask`, drops thin horizontal ruled strokes before merging words into line blobs, and returns crops from the gray image in reading order. The author flagged a real subtlety: a naive wide horizontal open erases solid text bands too, so the rule-drop keeps only thin components before subtracting — this is why the synthetic ruled-only page yields zero crops.

The eval harness is self-contained (onnxruntime + numpy + cv2 + PIL + fitz), imports no torch and no fontrecog, and is guarded under `__main__`. It auto-builds a folder→script manifest for the 12 dataset languages plus five Latin PDFs, collapses the three `other` label slots into one via a de-duplicated vocab, loads one session per model, and emits per-script accuracy, a collapsed confusion matrix, top1−top2 margins, and source-level vote accuracy. Strategy C is a documented numpy/PIL replica of fontrecog's letterbox, called out as such because importing the real one pulls torch.

### Flag-gated handwriting signal, end-to-end

`handwriting_prob: Optional[float] = None` is added to `SampleObs`, `DocPrior`, and `PageProbe`, and `ProbeConfig` gains `vlm_for_handwriting: bool = True` and `hw_threshold: float = 0.30` with `from_env` parsing of `IDP_PROBE_VLM_FOR_HANDWRITING` and `IDP_PROBE_HW_THRESHOLD`. Because the field defaults to `None` and the config param is keyword-only with a default, every existing construction and call site stays valid.

`decide_route` gains a keyword-only `handwriting_prob=None`. The handwriting branch sits inside the existing `if script == "latin":` case, before the printed return:

```python
if script == "latin":
    if handwriting_prob is not None and handwriting_prob >= cfg.hw_threshold:
        return RouteChoice(route=ROUTE_HANDWRITTEN, ocr_lang=SCRIPT_TO_PADDLE_LANG["latin"],
                           use_structure=has_table, reason="latin_handwritten")
    return RouteChoice(route=ROUTE_PRINTED, ...)
```

With `handwriting_prob is None` the function returns exactly what it did before. No non-Latin branch was modified, so `other`/`unknown`/low-conf still go to the VLM, mixed still goes to the VLM, and every confident non-Latin script still returns `ROUTE_VLM`. Targeted checks confirm latin+0.9 → handwritten, latin (none) → printed, devanagari+0.99 → vlm, telugu+0.99 → vlm.

### The extra VLM call is on the skip path only

In `probe.py::_observe`, the normal fallback fires when `obs is None or conf < onnx_min_conf or mixed`. The handwriting call is the `elif` after it:

```python
elif (cfg.vlm_for_handwriting and obs is not None and obs.script == "latin"
      and obs.script_confidence >= cfg.onnx_min_conf and not obs.mixed_scripts
      and vlm is not None and cfg.vlm_enabled):
    v = vlm.observe(pn, jpeg)
    ...
    if v is not None:
        obs.handwriting_prob = v.handwriting_prob
```

Being an `elif` matters: the confident-latin, non-mixed case is exactly the one the leading `if` evaluates false for, so this is the only place the previously-skipped VLM call is reintroduced, and it adopts only `handwriting_prob` (ONNX script/confidence untouched). Flag off, non-latin, low-conf, or mixed → the `elif` is never entered, so zero extra calls. Phase C resolves `hw` from the nearest sample when heterogeneous, else the doc prior (falling back to the sample when the prior has none), and threads it into both `decide_route` call sites and both `PageProbe` constructions.

### Line-crop extractor and the ruled-line subtlety

`extract_line_crops(gray, mask=None, *, min_height=10, max_height_frac=0.5, pad=3, min_width=15)` computes the ink mask when not supplied, removes ruled lines, dilates horizontally to merge words into one blob per line, keeps text-line-sized components, and crops from gray in `(y, x)` reading order. The rule-drop opens horizontally and then keeps only components with height `<= max(2, min_height//2)` before subtracting, so a solid text band (which also survives a wide horizontal open) is not mistaken for a rule and erased. The returned bbox is the padded, clamped box in analysis-image coordinates; the eval harness scales those boxes to full-res RGB itself via `_scale_box`. Synthetic tests cover ruled-only → 0, single band → 1 within the drawn band, blank → 0.

### Eval harness: labelling, strategies, and `other` collapse

The harness never imports torch or fontrecog (confirmed at import time) and guards all execution under `__main__`. The auto-manifest maps `dataset/verified_twice/<lang>/cropped_images/*.jpeg` to scripts via the authoritative `LANGUAGE_TO_SCRIPT` table and adds the five English PDFs as `kind=pdf, true_script=latin`; `__MACOSX` and dotfiles are skipped, and any unmappable folder/PDF is listed and skipped rather than labelled. The three `other` label slots (indices 7, 9, 11, confirmed against `lipika_script.labels.json`) collapse to a single `other` because `load_labels` builds a de-duplicated `vocab` and `collapse_label` maps each output index through `raw_labels[idx]`, so all three slots resolve to the same `other` column in the confusion matrix and accuracy.

Strategy A replicates `script_classifier._letterbox` (white pad to square, `cv2.resize INTER_CUBIC`, `/255`, NCHW). Strategy B cuts square-ish windows (≤2:1) along the longer axis, letterboxes each as A, and means the softmax over windows. Strategy C is a numpy/PIL replica of fontrecog's `letterbox` (PIL pad to square fill=255, `Image.BICUBIC`, `/255`, CHW), documented in both code and report as a replica because importing the real one pulls torch. Both models load with one `InferenceSession` each, reused across strategies; a missing model warns and skips, both missing exits 2. Output covers per-script top-1 accuracy, collapsed confusion matrix, top1−top2 margin stats, and source-level vote accuracy with the minimum crop count reported, written to `.agents/tasks/lipika-eval-results.md` plus a stdout summary.

`tests/test_probe.py` + `tests/test_line_crops.py` = 34 passed (27 baseline + 3 line-crop + 4 handwriting).
